# Участие в разработке

Спасибо за помощь в развитии CloudPayments PHP Client. При участии в проекте
соблюдайте [кодекс поведения](CODE_OF_CONDUCT.md).

## Ошибки и предложения

Перед созданием issue проверьте [существующие обсуждения](https://github.com/axcherednikov/cloudpayments-php-client/issues)
и воспроизведите проблему на последнем релизе.
Используйте шаблон ошибки или предложения: укажите версию библиотеки и PHP,
минимальный пример, ожидаемый и фактический результат.
Для нового метода API приложите ссылку на документацию CloudPayments.

Не публикуйте API-пароли, карточные данные, токены платежей и персональные данные.
Используйте тестовые данные; сообщения об уязвимостях направляйте приватно
по [политике безопасности](.github/SECURITY.md).

## Подготовка окружения

Нужны PHP `^8.1`, Composer и Git. Сделайте fork, клонируйте его и установите зависимости:

```bash
composer install
composer bin phpstan install
composer bin rector install
composer bin php-cs-fixer install
```

Зависимости инструментов изолированы в `vendor-bin/`.

## Изменения

Создавайте отдельную ветку от актуального `master` с префиксом `feat/`, `fix/`,
`docs/` или `chore/`. Открывайте pull request в `master`; прямой push в `master` запрещён.
Для крупных или несовместимых изменений сначала обсудите решение в issue.

- Сохраняйте структуру проекта, namespace `Excent\Cloudpayments`, строгую типизацию
  и совместимость с поддерживаемыми версиями PHP.
- Ограничивайте diff задачей и сохраняйте существующее публичное поведение,
  если изменение контракта не согласовано.
- Добавляйте тесты для нового или исправленного поведения. HTTP-вызовы в unit-тестах
  подменяйте тестовыми ответами, без реальных платежей и учётных данных.
- Для нового API-метода добавьте request DTO, response DTO при необходимости,
  метод в `src/Library.php`, запись в `CloudMethodsEnum` и тесты.
- При изменении публичного API обновляйте README и CHANGELOG.
- Не редактируйте вручную `vendor/`, сгенерированные артефакты и lock-файлы;
  используйте соответствующий инструмент, если их изменение необходимо.

## Проверки

Для изменений PHP-кода выполните проверки, используемые проектом:

```bash
composer test
make phpstan
make rector
make lint
```

`make phpstan` выполняет анализ уровня 8; `make rector` и `make lint` проверяют
код без применения исправлений. Для исправления стиля используйте `make fixcs`.

Для изменений только в документации проверьте ссылки, примеры команд и итоговый diff.
В PR перечислите реально выполненные проверки и объясните, если нужная проверка
не была выполнена. CI проверяет PHPUnit на PHP 8.1–8.5, PHPStan, Rector и PHP CS Fixer.

## Pull request

Опишите проблему, результат изменений, совместимость и проверку поведения.
Укажите связанный issue, если он есть, и дождитесь review и результатов CI.
Изменения в deployment или release workflow должны разрешать публикацию только
из `master` либо из релизного тега на коммите, включённом в `master`.
